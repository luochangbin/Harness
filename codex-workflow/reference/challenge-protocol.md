# 有限质询协议（方案核对）

设计阶段方案核对深度：介于 brainstorming（问太少）与 grilling（问太多）之间。
核心模型：**清单完成** — 每维度有明确答案即过，不追求穷尽；有缺口才追问。

## 六维度清单

| # | 维度 | 通过标准 |
|---|------|---------|
| 1 | 目标/非目标 | 目标可验证、非目标明确、验收标准能写成测试 |
| 2 | 边界与失败模式 | 至少列出 3 种失败场景 + 降级策略 |
| 3 | 方案取舍 | 每个关键决策有替代方案 + 选择理由 |
| 4 | 数据流/一致性 | 状态变更、数据流、并发场景无矛盾 |
| 5 | 测试策略 | 每个已声明验收场景映射到测试；默认不补充或推导 E2E |
| 6 | 兼容/迁移 | 破坏性变更、影响范围明确 |

## 质询规则

- 每维度 agent 先自述答案（基于澄清产出），再核对缺口
- 有缺口才追问，**每维度最多 2 问**
- **总预算 ≤ 12 问**，到预算硬停
- 未解决的缺口 → 标记「已知风险」记录进 design.md「质询记录」章节，不无限纠缠
- E2E 仅在用户当前请求或 spec 已明确要求时参与测试策略；不得根据“产品通常需要 E2E”自行补充
- 质询结果必须落盘 design.md 的「质询记录」章节 — 审计痕迹永久保留

## 分级

| 档位 | 质询维度 |
|------|---------|
| full | 全部 6 维 |
| tweak | 3 维：目标/非目标、边界与失败模式、测试策略 |
| bugfix | 跳过（不建 AR） |

## 三类问题规则（交互模型）

| 类型 | 判定 | 行为 |
|------|------|------|
| A 可逆/低影响 | 命名、格式、实现细节、可逆选择 | **不问**，自行决策；假设记录进 design.md「已知风险」；用户可事后纠正 |
| B 质询维度 | 设计缺口核查 | 置信度不参与判定；清单有缺口才问（预算内） |
| C 不可逆/高影响 | 改变已确认需求含义、破坏兼容、数据迁移、不可逆删除、归档冲突和最终归档 apply | **必问**，无论置信度 |

**规则一句话**：可逆的决策别问，不可逆的必问，质询维度不按置信度跳过。
