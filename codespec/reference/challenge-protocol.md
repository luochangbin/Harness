# 有限方案核对

| 维度 | 核查问题 |
|------|----------|
| 目标/非目标 | 范围是否明确，结果能否验收？ |
| 边界与失败模式 | 本次真实相关的失败路径如何处理？不要凑固定数量。 |
| 方案取舍 | 关键选择有何依据，是否有更简单方案？ |
| 数据流/一致性 | 状态、数据流和并发是否一致？ |
| 测试策略 | 验收场景能否映射到实际测试/验证步骤？ |
| 兼容/迁移 | 是否破坏兼容，部署和回滚有什么要求？ |

full 核对六维；tweak 核对目标/边界/测试三维；bugfix 走最小回归测试闭环。

有真实缺口才问，每维最多两问、总计最多十二问。预算耗尽且仍有影响范围/方案/验收的阻塞问题时停止推进，不能靠记为风险跳过。
可延期问题写明影响与处理方式；可逆细节自行决定，未授权的高影响或不可逆选择交给用户。

只记录新增决策、真实问答和未解决风险，不抄写每维自述。
有 design.md 时记录在设计历史章节；省略设计的 tweak 记录在 spec.md「方案核对」。
spec 的正式验收场景是唯一需求依据，测试策略和 tasks 只引用它。
